# Weather Researcher

`Weather Researcher` — это веб-приложение, созданное для исследователей и энтузиастов, которые хотят отслеживать, сохранять и анализировать погодные данные из разных городов мира. Пользователи могут просматривать актуальную погоду, подписываться на обновления для интересующих их городов и создавать "снимки" (snapshots) погоды для последующего анализа.

## Ключевые возможности

*   **Просмотр погоды**: Получение актуальных погодных данных для тысяч городов по всему миру.
*   **Аутентификация пользователей**: Безопасная регистрация и вход в систему с использованием JWT.
*   **Персональные подписки**: Зарегистрированные пользователи могут подписываться на города, чтобы отслеживать погоду в личном кабинете.
*   **Создание "снимков"**: Возможность сохранять текущие погодные условия в виде "снимка" для истории и анализа.
*   **Фильтрация и сортировка**: Мощные инструменты для фильтрации и сортировки данных как на главной странице, так и в личном кабинете.
*   **Пагинация**: Удобная навигация по большим спискам данных.

## Архитектура

Проект построен с использованием **Чистой Архитектуры (Clean Architecture)**. Этот подход обеспечивает четкое разделение ответственностей (Separation of Concerns), слабую связанность компонентов и высокую тестируемость.

Приложение разделено на три основных слоя:

1.  **`Domain`**
    *   **Назначение**: Ядро приложения. Содержит бизнес-сущности (`User`, `City`, `Snapshot`, `Country` и др.), которые представляют основные объекты предметной области.
    *   **Ключевые характеристики**: Этот слой не имеет зависимостей от других слоев проекта. Он полностью независим от базы данных, пользовательского интерфейса и внешних сервисов. Это делает бизнес-логику переиспользуемой и стабильной.

2.  **`UseCases`**
    *   **Назначение**: Оркестрация бизнес-логики. Этот слой определяет, как именно взаимодействуют доменные сущности для выполнения конкретных задач (например, регистрация пользователя, создание снимка погоды).
    *   **Ключевые компоненты**:
        *   **Абстракции**: Определяет контракты для взаимодействия с внешним миром, такие как `IReadRepository`, `IWriteRepository`, `IAuthService`, `IWeatherAPI`, `IHasher`. Это соответствует **Dependency Inversion Principle**.
        *   **Specifications**: Реализует **паттерн Спецификация** (`CityCriteriaSpec`, `SnapshotFilterCriteriaSpec`) для инкапсуляции логики запросов к данным. Это позволяет создавать гибкие и переиспользуемые критерии фильтрации.
        *   **DTO**: Объекты (`DataToAuth`, `AuthResult`) для передачи данных между слоями, не раскрывая внутреннюю структуру доменных моделей.

3.  **`Infrastructure`**
    *   **Назначение**: Реализация абстракций, определенных в слое `UseCases`. Этот слой содержит весь "клей", который связывает приложение с внешним миром.
    *   **Ключевые компоненты**:
        *   **ASP.NET Core MVC**: Обрабатывает HTTP-запросы и ответы. Контроллеры (`HomeController`, `OwnCabinetController`) служат точкой входа, вызывая логику из слоя `UseCases`.
        *   **Entity Framework Core**: Реализует интерфейсы репозиториев (`MySqlRepository`) для работы с базой данных MySQL. Используется **паттерн Репозиторий** и **Unit of Work** для абстрагирования логики доступа к данным.
        *   **Внешние сервисы**: Клиент для работы с API OpenWeatherMap (`OpenWeatherMapApi`).
        *   **Аутентификация**: Реализация JWT-аутентификации (`JwtCookieManager`, `AccessTokenHandler`) и хеширования паролей (`Pbkdf2Hasher`).
        *   **UI**: Представления Razor для отрисовки HTML-страниц.
        *   **Builder**: Классы `IndexPageBuilder`, `SnapshotPageBuilder` и др. используются для инкапсуляции сложной логики построения моделей представления (ViewModel), что делает контроллеры более чистыми.

### Схема взаимодействия слоев

```
+-------------------------------------------------------------------------+
| Infrastructure (ASP.NET, EF Core, MySQL, OpenWeatherMap API, JWT)       |
|       ^                                                                 |
|       | Implements                                                      |
|       v                                                                 |
+-------------------------------------------------------------------------+
| UseCases (Interfaces, DTOs, Specifications, Application Logic)          |
|       ^                                                                 |
|       | Uses                                                            |
|       v                                                                 |

+-------------------------------------------------------------------------+
```

##  Технологический стек

*   **Бэкенд**: C# 12, .NET 8, ASP.NET Core MVC
*   **База данных**: MySQL 9.0
*   **ORM**: Entity Framework Core 6.0 с провайдером `Pomelo.EntityFrameworkCore.MySql`
*   **Аутентификация**: JSON Web Tokens (JWT)
*   **Контейнеризация**: Docker, Docker Compose
*   **Внешние API**: [OpenWeatherMap API](https://openweathermap.org/api) для получения данных о погоде
*   **Фронтенд**: HTML5, CSS3, JavaScript (ES6), jQuery (для AJAX-запросов)
*   **Паттерны проектирования**:
    *   Repository & Unit of Work
    *   Specification
    *   Builder
    *   Dependency Injection (встроен в ASP.NET Core)

##  Схема Базы Данных

База данных `weather_for_researchers` спроектирована для хранения информации о пользователях, городах, странах и их погодных данных.

*   `countries`: Справочник стран.
*   `cities`: Справочник городов с привязкой к странам.
*   `users`: Информация о зарегистрированных пользователях (логин, хеш пароля, соль).
*   `userscities`: Таблица-связка для хранения подписок пользователей на города (многие-ко-многим).
*   `snapshots`: Сохраненные пользователями "снимки" погоды в определенных городах в определенное время.
*   `accesstoken`: Хранит активные токены доступа пользователей для управления сессиями. Старые токены автоматически удаляются с помощью события в MySQL.

Скрипты для создания и начального наполнения таблиц находятся в директории `/sql`.

## Запуск проекта

Проект полностью контейнеризован с помощью Docker, что делает его запуск быстрым и независимым от окружения.

### Требования

*   [Docker](https://www.docker.com/products/docker-desktop/) установленный и запущенный на вашем компьютере.

### Инструкция по запуску

1.  **Клонируйте репозиторий**:
    ```bash
    git clone https://github.com/your-username/WeatherResearcher.git
    cd WeatherResearcher
    ```

2.  **Запустите проект с помощью Docker Compose**:
    Выполните команду в корневой директории проекта (где находится файл `docker-compose.yml`):
    ```bash
    docker-compose up --build
    ```

3.  **Откройте приложение в браузере**:
    После успешного запуска приложение будет доступно по адресу:
    [http://localhost:8080](http://localhost:8080)

База данных будет доступна извне по порту `3306` хост-машины, что позволяет подключаться к ней с помощью любого клиента MySQL.
